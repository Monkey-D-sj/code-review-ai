name: code-review-methodology
description: 审查任何 diff 前,先按本 skill 判定每个变更函数是否自包含、是否需要查上下文以及查多深。决策表是 eval 与 post-commit hook 共享的唯一事实来源,与 code-review-* 语言 skill 配合使用。
---

对每个变更函数,先判断它是否自包含:只凭 diff 与该函数自身的代码,能否完整判断这次改动的正确性与影响范围;不能则检查其调用方/上下文:

必须检查上下文(高风险):
- 接口变更:函数删除了参数,或改变参数的类型/顺序/返回类型;新增必填参数。
- 异常变更:之前返回 None / 错误码,现在改为抛异常。
- 契约变更:同步改为异步,或改动引入了阻塞工作/锁。
- 调用方依赖的行为:改动改变了调用方依赖的语义、新增或移除跨模块调用、重接路由/DI。
- 被其他模块调用:函数被其他模块调用且改动可能破坏它们。
- 动态语言:Python/JS 破坏性改动没有编译器拦截被破坏的调用方。
- 跨服务:任何 RPC/API 改动(检查消费方是否就绪)。

无需检查上下文(低风险):
- 纯内部:只改了函数体(算法/优化/注释/改名/格式化),签名、返回类型与异常语义不变,且没有改变调用方依赖的行为。
- 新增带默认值、保持现有行为的参数。
- 私有/小范围:私有函数调用方少,且所有调用点已适配。

拿不准 → 按「需要上下文」处理。
检查深度:跨服务、删除的函数、被跨模块调用的接口变更需要最深检查(用 query_graph 沿上游递归追到受影响业务入口);其他需要上下文的改动只需检查其调用方;私有/小范围改动只需读直接调用点。
