# 真实仓库解析基线

测试对象：当前工作区 `code-review-ai` 仓库快照（包含本轮未提交修改）。

测试日期：2026-08-20

## 文件解析率

| 指标 | 结果 |
|---|---:|
| 源码文件 | 188 |
| Python | 129 |
| TypeScript/Vue | 25 |
| Java | 34 |
| 解析成功 | 188 |
| 解析失败 | 0 |

这里的“解析成功”指项目真实索引流程能够读取文件、建立 AST 并完成索引；Vue 文件按项目逻辑先提取 script 再解析。

### 关键比例

- 文件解析率：`188 / 188 = 100%`
- call 边静态定点率：`1,981 / 5,899 = 33.58%`
- 排除 dynamic 后，call 边 resolved 比例：`1,981 / (1,981 + 1,846) = 51.78%`
- 所有图边 resolved 比例：`3,902 / 8,168 = 47.77%`

## 如何解读

文件解析率回答“代码能不能被读懂并建立节点”；resolved 比例回答“调用或依赖目标能不能唯一绑定到仓库节点”。后者较低不等于 parser 失败，主要原因包括：

- Python/TypeScript 的动态调用；
- 第三方库和仓库外依赖；
- 反射、回调、运行时属性访问；
- 当前仓库测试代码中的故意负例；
- 未建立完整类型流或构建配置关系。

这份结果是单个仓库快照基线，不代表所有 GitHub 仓库的平均值。后续应使用固定 commit 的多仓库 corpus 重复同一流程。
