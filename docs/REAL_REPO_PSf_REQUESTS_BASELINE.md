call 边只有 36.44% 能直接绑定到仓库内唯一目标；这不是文件解析失败，而是第三方依赖、动态属性、运行时调用和无法在仓库内找到实现的符号造成的。若只看静态图构建，contains、extends 等结构边的表现明显高于 call 边。

该结果是单个固定 commit 的外部基准，不代表所有 GitHub Python 项目的平均值。

## 排除外部依赖后的估算

因此可以给出两个内部解析率：

- **已识别仓库内部调用定点率**：`892 / (892 + 95) = 90.37%`
- **保守内部调用定点率**（把未知项也视为可能的仓库内调用）：`892 / (892 + 95 + 257) = 71.70%`

90.37% 是偏乐观的“已识别内部目标”指标，71.70% 更适合作为对外汇报的保守指标。两者都不是人工标注后的 precision/recall，因为 unresolved 目标缺少真实 gold label；要得到严格准确率，还需要人工标注一批调用点。
